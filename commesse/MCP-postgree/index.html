Un collegamento MCP. Un token per ogni gestionale.

Verifica il backend, crea una credenziale dedicata e avvia ChatGPT con l'istruzione di base. Il token viene generato solo in questo browser: l'abilitazione agli schemi avviene successivamente sul server.

01

Controllo di disponibilità e lettura versione.

L'endpoint /health non richiede token. Il pulsante non crea, configura o distribuisce server Render.
02

Token del gestionale

Generazione crittografica locale e impronta di registrazione.

Queste sono richieste di configurazione, non permessi concessi. Schemi, tabelle e colonne saranno autorizzati dall'amministratore nel secret store del backend.

Nessun token generato
Token non ancora attivo. La generazione non registra automaticamente il token sul server. La policy va completata con tabelle/colonne e approvata dall'amministratore. Non incollare il token nella chat AI.
03

Prova del contratto MCP

Verifica autenticazione, tool unico e comando Init.

Dopo avere registrato l'impronta nella configurazione protetta del server, puoi collaudare direttamente il protocollo Streamable HTTP. Il token non viene salvato dal sito.

Il test richiede un backend configurato e raggiungibile.

Nessun test eseguito.

Per la prova dal browser, il backend deve autorizzare l'origine GitHub Pages con CORS. Il test non concede permessi e non modifica record.

04

Avvia ChatGPT

Bootstrap iniziale come in Tiralinee MCP.

L'istruzione include la procedura corretta di inizializzazione e il riferimento al contratto. Non contiene token, hash, password o stringhe di connessione.

Il collegamento MCP deve essere già configurato nel client GPT: aprire una chat non installa automaticamente un connettore.
